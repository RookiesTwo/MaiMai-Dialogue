## 总体方向

以一个项目、一个 namespace、导出一组 Resource Pack＋Data Pack 作为组织方式。优先打通“新建 → 编辑对话 → 预览 → 保存 → 导出”的创作闭环，再增加视觉、音频、动画和已有内容包导入。

沿用七区工作台、直角组件和白色／浅灰色／亮蓝色配色。一次打开一个本地项目，外部资源只读引用；先手动保存，不加入多人协作、远程发布或任意位置音频 seek。

## 实现步骤

各步骤分别交付，完成一个步骤后即可构建、体验和反馈。

| 步骤 | 实现内容 | 完成标准 |
| --- | --- | --- |
| 1．项目与编辑状态 | 新建、打开、保存、关闭本地项目；名称和 namespace；独立于 View 的文档状态、未保存标记、撤销／重做；项目格式版本，允许保存未填写完整的草稿。 | 保存重开内容一致；窗口变化不丢编辑内容；关闭未保存项目时提供保存、放弃、取消。 |
| 2．左侧资源浏览器 | “项目 → 资源类型 → 文件夹 → 资源”树形结构；选择、打开、搜索及已开放类型的创建、复制、删除；单击查看属性，双击打开编辑。 | 浏览器、文档、属性面板选择一致；阻止删除被引用资源；尚无编辑器的分类保持占位。 |
| 3．基础 Dialogue 与 Speaker 编辑 | Speaker 名称；步骤新增、删除、复制、排序；Markdown 正文、说话人、唯一 End；结束方式、选项文字、图标、跳转目标；默认内置 Theme 和空场景。 | 能制作三句对白、两个分支；选项顺序稳定；支持撤销／重做。 |
| 4．基础游戏内预览 | 注入工程内容，复用真实布局、渲染和播放逻辑；从头播放、推进、选择选项、停止、重新开始；独立 session。 | 无需导出即可预览和跳转；不执行真实命令、不写玩家进度；结束时释放预览资源。 |
| 5．校验与双包导出 | 必填字段、ID、引用、运行时 Codec 检查；定位资源与字段；生成两个 pack.mcmeta；Dialogue 序列化一次写入双包，其他定义进入资源包。 | 无效内容阻止导出；双包 Dialogue 完全一致；失败不留下半套成品；用户在测试世界验证加载播放。 |
| 6．素材与 VisualAsset | 游戏内文件选择、图片和声音导入；素材复制到工程；差分、采样和 sound event 映射；临时开发资源包与显式刷新。 | 不依赖原素材路径；差分和声音可选择；保存状态与素材加载状态分开显示。 |
| 7．Scene 与 Presentation | 背景、VisualObject、Filter、对话框区域；画布选择、拖动、数值输入；Presentation 引用、内联及既有覆盖规则。 | 准确定位；切换步骤重建累计场景状态；保存保留引用与覆盖意图。 |
| 8．Theme 编辑 | 对话框、正文、选项、间距和控件样式；真实渲染预览；复用现有主题字段。 | 主题可应用到对话；不改变编辑器自身样式；共享引用更新一致。 |
| 9．音频编辑 | Dialogue BGM、Speaker／Step 打字音、静音与继承、动作音效和 BGM；试听与播放反馈。 | 保持未设置、继承、明确停止／静音的语义；遵守玩家音量设置；关闭不遗留声音。 |
| 10．SceneAction 与时间轴 | 引用或内联动作、目标、延迟、时长、缓动、blocking、关键帧、单次变化；预设、时间定位与播放；区分初始摆放和关键帧编辑。 | 复用运行时状态计算；检测同一步骤同目标属性写入冲突；拖动不重复触发声音。 |
| 11．高级 Dialogue 行为 | requires、模拟 ProgressNode、随机正文候选、打字速度、skip_summary、must_complete、选项命令；展示模拟结果。 | 可验证条件和正文候选；命令与进度只模拟；现有 Dialogue 字段全部有入口。 |
| 12．引用管理与大型项目导航 | 引用查找、重命名／移动同步引用、只读依赖浏览、Dialogue 关系图。 | ID 修改后引用同步；依赖来源清楚；关系图定位对话，保留步骤列表＋End 结构。 |
| 13．已有内容包导入 | 文件夹或 ZIP 导入资源包／数据包；预检转换工程；保留引用、内联与字段省略语义。 | 双包 Dialogue 不一致时选择来源；不静默丢失不支持内容；导入保存再导出保持运行语义。 |

步骤 1～5 是首个可用版本：验收纯文本与分支对话，不等待素材、立绘或动画。步骤 6～11 完成现有七类资源编辑；步骤 12～13 完善大型项目维护与迁移。

## 架构与接口边界

- 业务集中在 editor 子项目，分为项目存储、编辑文档、资源索引、分区编辑器、预览和导出；不堆进工作台 View。
- 草稿与运行时模型分离，允许暂时无效，通过校验后转现有模型；内部步骤标识、选择状态和撤销记录不导出。
- 通过 DialogueContentLookup 注入工程快照，复用 Codec、资源解析、DialogueSession 和场景渲染，不替换游戏全局内容仓库或 controller。
- 仅按阶段增加必要主 MOD 接口；时间轴阶段增加外部时间采样／渲染入口，素材与校验阶段增加资源解析接口；保持 API 行为、JSON 格式、网络协议兼容。
- 项目只有一份 Dialogue；预览和导出使用相同的已校验内容。
- 文件操作在后台执行，ModernUI View 与 Minecraft 资源更新遵守各自线程边界。

## 验证规则

- 每步通过 IDEA MCP 执行 Build Editor 和 build_project；涉及主 MOD 接口时补相应检查。不得直接从命令行执行 Gradle。
- 启动统一使用 Client，同时加载主 MOD 与编辑器。
- 仅针对必要的数据逻辑编写测试，如保存重开、引用维护、Codec 转换、双包一致性和预览副作用隔离。
- 不编写 UI 显示、布局尺寸或绘制效果单元测试；不使用模型视觉、截图识别或 Computer-use 验收。
- 每步提供构建结果及操作清单，由用户验收实际显示和交互，再更新验收状态。
- 按顺序开放功能，不提前加入后续阶段业务；实施时同步 editor/README.md 和本地 .project-notes/dialogue-editor-design.md。
